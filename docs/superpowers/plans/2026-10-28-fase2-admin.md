# Fase 2 (banco, login com papéis e admin) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Notícias, agenda, diretoria e ex-presidentes passam a viver no PostgreSQL e são editados num `/admin` com papéis admin/revisor/editor, sem mudar o HTML público.

**Architecture:** A regra de negócio fica em `lib/admin/*.ts` (funções que recebem `db` e o usuário, sem importar nada do Next), testável com `node --test` contra um Postgres real. As Server Actions em `app/(admin)/admin/**/acoes.ts` só obtêm a sessão, chamam essas funções e fazem `revalidatePath`. O site público continua estático, lendo `lib/content.ts`, que passa a consultar o banco.

**Tech Stack:** Next 16.4 (App Router), React 19, drizzle-orm 0.45 + drizzle-kit 0.31 + `postgres` 3.4, better-auth 1.7 (plugin `admin`), zod 4, sharp 0.35, @aws-sdk/client-s3 3, Playwright (Python) para os testes de navegador.

**Spec:** `docs/superpowers/specs/2026-10-28-fase2-admin-design.md`

## Global Constraints

- O HTML público das 22 rotas não muda: `python testes/paridade.py <ref> <novo>` dá 22/22 contra o main de antes desta fase.
- `site.js` não muda e não roda no admin; o admin pode ter Client Components, o site público não.
- Código em `lib/` usa imports relativos com extensão `.ts` (roda direto em `node --test`); nada em `lib/` importa `next/*`, exceto `lib/auth-servidor.ts`.
- Datas de conteúdo são strings `AAAA-MM-DD` (`date(..., { mode: 'string' })` no Drizzle), nunca `Date`, para não sofrer fuso.
- Papéis: `admin | revisor | editor`. Situações de notícia: `rascunho | revisao | publicada | devolvida`.
- Toda Server Action chama `pode()` de novo antes de agir; esconder botão nunca é a única proteção.
- Mensagens de interface em português, como no site.
- Upload: JPG, PNG ou WebP, até 8 MB, largura máxima 1600 px.
- `npm test` roda só testes sem banco (`lib/**/*.test.ts`); `npm run test:db` roda `lib/**/*.db-test.ts` contra `TEST_DATABASE_URL`.

## Review Focus

1. Duas notícias com o mesmo título: a segunda deve ganhar slug `-2`, não estourar erro de chave única. (Task 6)
2. Editor chamando a Server Action de publicar direto (formulário adulterado): o servidor recusa. (Task 6)
3. Todas as notícias despublicadas: home e `/noticias` não podem quebrar com lista vazia (pendência da Fase 1). (Task 3)
4. Conta desativada no meio de uma sessão enviando um formulário: recusado, sessão some. (Task 4)
5. Notícia despublicada: `/noticias/<slug>` passa a 404 e some da home e da lista. (Task 12)
